# Intelligence and performance roadmap

Modhunter has two permanent development objectives. Expand what the app can establish about each installed file and continuously reduce the cost of establishing it. The existing MO2, desktop, standalone, game-mode, theme, accessibility, progression and recovery commitments continue alongside this work.

## Performance acceptance

Pursue **0.1 ms or less for individual local operations wherever achievable**. Measure wall time through the completed result. Keep the same inputs, visible rows, visual fidelity, scan coverage, validation, result ordering and integrations on both sides of every comparison. Report external network, disk, rendering and MO2 time separately from pure computation. Background dispatch ends when the result is available to the caller.

Record revision, hardware, software, fixture or real profile, row and file counts, cache policy, raw samples, median, p95/p99 where enough samples exist, CPU time, peak memory, throughput and end-to-end completion time. Distinguish an empty application cache from an evicted OS cache. Interleave before/after runs, compare actual outputs, and retain the last verified equivalent-work performance floor. Keep private collection data and account material local.

Run targeted benchmarks with each change to scanning, matching, extraction, catalog delivery, search, sorting, native bridge or installation preparation. Run full-scale end-to-end benchmarks for release candidates. The full collection is the workload. A count cap, hidden row, skipped file, virtualized viewport, weaker validation, older cached answer or early dispatch receipt invalidates a speed comparison.

## Product workstreams and acceptance

- **Exact-file updates.** Identify game, project, installed file and provider update chain. Resolve metadata, archive identity, versions, historical releases and variant information against the same file. Retain MO2's assessment and any evidence that supersedes it. An independently versioned sibling must never supply a target. Cover patches, translations, different runtimes, withdrawn files, prereleases and unresolved identities. Keep the AE Bone Wolf optional patch as a permanent regression.
- **Watchtower.** Add projects, files, creators, feeds, posts and page regions by URL. Track many-to-many associations, folders, tags, keywords, diffs and source history. Test discovery, import/export, scheduling, notifications, session expiry, restart and offline recovery. A page change requires exact installed-file evidence before it can become an update recommendation.
- **Retrieval and extraction.** Evaluate APIs, webhooks and feeds first, then HTTP validators, embedded structured content, DOM extraction, isolated browser rendering and optional semantic assistance. Compare Scrapy, Playwright, Crawl4AI, Firecrawl, changedetection.io and native alternatives on the same pages. Measure completeness, false changes, account boundaries, resource use and full latency. Select an engine by workload. Preserve the last successful observation and record retrieval, parser and access failures separately.
- **Health and intelligence.** Associate bugs, advisories, requirements, conflicts, patches and fixes with installed versions, runtime, profile and load order. Record original URL, publication and observation times, affected range, source authority, confidence and resolution. Show these findings in the Vault, Workshop and Watchtower. Reuse structured evidence and corrected identities across desktop, plugin, standalone and MCP where those entry points have authority.
- **Reference parity.** Track WhimWatch's providers, settings, creator and pack workflows, previews, selective updates, backup and rollback. Track MCP–MO2 live control, discovery, downloads, load order, conflicts, VFS and synchronization. Track houseCARL record and asset analysis, patching, Papyrus, SKSE, FaceGen and distributor configuration. Pin upstream release and source identity. Each capability needs an actual operation, expected observation, receipt and limitations. Keep advertised, fixture-tested and real-environment coverage distinct.
- **Production acceptance.** Verify the selected MO2 instance and shared paths. Baseline every existing mod, profile, ordering, overwrite, game/configuration and saves. Keep existing content read-only. Test new real archives through Modhunter and the native installer only after proving exact new ownership and disabled-from-install behavior in isolation. Verify update and rollback exclusively on owned test content. Compare all protected state after cleanup. Bind production installer, installed plugin, shortcuts, restart and reconnection evidence to the exact release before promotion.
