# WhimWatch parity: Modhunter 0.11.0 implementation and acceptance map

**Updated:** 2026-11-14. **State:** release candidate implementation, with final candidate-bound runtime acceptance still required.

This document accounts for all **52 findings** in the supplied `Modhunter-WhimWatch-Parity-Audit.md`, which compared WhimWatch 0.4.2 with shipped Modhunter 0.10.2. It maps those findings to the current 0.11.0 source and identifies the workflows that remain narrower, manual, excluded, or unverified. It is not a declaration of complete workflow parity or a substitute for the release's passing receipts.

The [0.10.0 reference inspection](whimwatch-parity-0.10.0.md) remains the historical source, license and packaged-asset inventory. Its interpretation that existing MO2 installation authority or profile-text backup covered the missing authenticated acquisition and actual-file recovery workflows is superseded by the supplied 0.10.2 audit and this implementation map. A profile-text backup is not a backup of replaced mod content. Opening a website is not a managed archive download.

## How to read the status

**Implemented** means the integrated candidate contains the described workflow, with the cited verification coverage. It does not mean every provider or final Windows candidate has passed. **Equivalent** means the user outcome is adapted to exact MO2 ownership rather than reproducing Sims-specific semantics. **Scoped** means a material subset or restriction is explicit. **Manual** means the remaining decision occurs through user review or a native MO2 dialog. **Excluded** means the behavior is intentionally outside this target. **Pending proof** identifies an acceptance requirement that code presence, mocks or cross-compilation cannot close.

Verification abbreviations in the tables:

- **U:** Rust or deterministic JavaScript/Python unit and protocol fixtures. These check policy and state transitions, not a real provider login.
- **C:** required real Chromium interactions against the shipped UI and a deterministic native bridge. Final candidate receipt required.
- **W:** required actual Windows/WebView2 or MO2 runtime fixture. Final candidate receipt required.
- **L:** permitted real-provider, personal-game or specified-version acceptance. These environments have not been exercised by this implementation pass.

These categories are not a parity percentage. A row can have a useful implementation and still have an unmet acceptance boundary.

## The candidate's exact authority chain

The classified workflow begins with an explicit current offer, not with a changed page or a source's publication date. The native host derives known provider file identity, retains only the durable identity hash and user decision, and creates a single-use browser lease for the selected request. Navigation IDs, observed redirects and actual current-document/download addresses prevent another same-host page or popup from borrowing that decision. An expired, changed or unsupported selection must be reopened through current discovery.

WebView2 transfer approval only permits bytes to enter the owned staging area. Ready state requires finalized archive bytes and a digest. The next approval is an archive/target review. That review compares exact installed ownership, source compatibility, native profile/runtime/lifetime and original bytes. Unambiguous selected game-data content is repackaged into a new verified ZIP; unresolved installer-dependent content remains the original verified archive with advisory review.

The MO2 service obtains an actual native mutation lease, checks the game/process/context again, captures and verifies previous mod contents, then invokes MO2's native installer. The result must confirm the exact target before a completed post-install identity is sealed. Lost acknowledgement or another target does not become a success by assumption. Retained unresolved receipts remain visible and cannot be casually discarded. Restore separately verifies the current tree against the sealed post-state and refuses later edits; it preserves copies when recovery is ambiguous.

The shared browser/capture/job generation boundaries are durable facts. Raw download URLs and browser session secrets are not turned into reusable renderer or MO2 credentials. A stored archive receipt can be revalidated without reconstructing network download authority.
